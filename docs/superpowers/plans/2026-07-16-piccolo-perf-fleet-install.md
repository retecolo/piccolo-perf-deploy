# piccolo-perf Fleet Install & Prometheus Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an Ansible project that idempotently rolls piccolo-perf out across a fleet of Unix/Linux hosts, serves its topology config over HTTPS from one central point, and brings every host's Prometheus (existing or new) to a hardened baseline: bound to the mesh VPN interface only, TLS-terminated with a centrally-issued Let's Encrypt wildcard cert, and firewalled as defense-in-depth.

**Architecture:** Three Ansible roles (`piccolo_perf`, `config_server`, `prometheus_hardened`) plus a `cert_issuer` role that runs once on the control node via DNS-01 ACME and pushes the resulting wildcard cert to the fleet on every renewal. All network services bind exclusively to each host's mesh-VPN IPv6 address (looked up dynamically via Ansible facts), never to `0.0.0.0`/`::`.

**Tech Stack:** Ansible ≥2.15, Molecule (docker driver) for role testing, certbot with a DNS-01 plugin, nftables, systemd, nginx (config server only). Target OS for the reference implementation: Debian/Ubuntu family (`apt`); other families are a documented follow-up, not built here.

## Global Constraints

- All service bind addresses use the mesh VPN interface's IPv6 address, resolved dynamically per host — never hardcoded, never `0.0.0.0`/`::`.
- No secret (DNS API token, basic-auth password) is ever hardcoded in a template or default; all such values come from Ansible Vault and the role fails fast with `ansible.builtin.assert` if they're unset.
- Every systemd unit this plan authors from scratch (piccolo-perf, Prometheus) keeps `NoNewPrivileges=true` and drops root where the upstream unit already does (piccolo-perf's `DynamicUser=yes`, Prometheus's static `prometheus` user).
- TLS material is never generated by these roles — it is consumed from `/etc/letsencrypt/live/<mesh_domain>/{fullchain,privkey}.pem` on the control node and pushed out; only the `cert_issuer` role/playbook touches the ACME client.
- Every role has a Molecule scenario using the `docker` driver with a systemd-capable base image; every scenario's default test sequence (`molecule test`) must pass, including the built-in idempotency check (second converge reports zero changes).

```markdown
# piccolo-perf fleet install

Ansible project to roll out [piccolo-perf](https://github.com/retecolo/piccolo-perf)
exporters fleet-wide and bring every host's Prometheus to a hardened baseline:
mesh-interface-only binding, native TLS, and a centrally-issued Let's Encrypt
wildcard certificate.

Full design: `docs/superpowers/specs/2026-07-16-piccolo-perf-fleet-install-design.md`

## Prerequisites

- A mesh VPN with a **consistent interface name** across the fleet, providing
  IPv6 addressing and (ideally) internal DNS resolving `<hostname>.<mesh_domain>`.
- Inventory hostnames matching the mesh VPN's hostnames (see `inventory/hosts.example.ini`).
- A DNS provider supported by a certbot DNS-01 plugin, for the wildcard cert.
- Ansible Vault secrets (create before first run):
  - `cert_issuer_dns_credentials_content` — DNS provider API credentials file contents
  - `prometheus_basic_auth_password_hash` — bcrypt hash (`htpasswd -nbBC 10 admin '<pw>'`)

## Bootstrap order

1. Copy `inventory/hosts.example.ini` to `inventory/hosts.ini` and edit it, and
   `inventory/group_vars/all.yml` to match your fleet's topology.
2. Set the two Vault secrets above.
3. `ansible-playbook -i inventory/hosts.ini playbooks/cert-issue.yml` — issues the
   wildcard cert and distributes it to every host currently in inventory (the
   distribution is triggered automatically by certbot's `--deploy-hook`).
4. `ansible-playbook -i inventory/hosts.ini playbooks/site.yml` — deploys
   piccolo-perf, the config server, and hardened Prometheus.
5. `ansible-playbook -i inventory/hosts.ini playbooks/verify-fleet.yml` — smoke-tests
   every deployed service over HTTPS via the mesh interface.

## Role testing

Each role has a Molecule scenario:

```sh
cd roles/piccolo_perf && molecule test
cd roles/config_server && molecule test
cd roles/prometheus_hardened && molecule test
```

`cert_issuer` has no Molecule scenario — DNS-01 issuance can't run in CI. It's
covered by `ansible-lint` and `ansible-playbook --syntax-check` only; test it
manually against a real DNS zone before relying on it.
```

- [ ] **Step 6: Create `roles/piccolo_perf/molecule/default/prepare.yml`**

```yaml
---
- name: Prepare
  hosts: all
  become: true
  tasks:
    - name: Install prerequisites present in the test image
      ansible.builtin.package:
        name: [iproute2, openssl, curl, tar, nginx, ca-certificates]
        state: present

    - name: Create a dummy interface to simulate the mesh VPN
      ansible.builtin.command: ip link add dummy0 type dummy
      register: dummy_link
      changed_when: dummy_link.rc == 0
      failed_when: dummy_link.rc != 0 and 'File exists' not in dummy_link.stderr

    - name: Bring the dummy interface up
      ansible.builtin.command: ip link set dummy0 up
      changed_when: false

    - name: Assign a ULA IPv6 address to the dummy interface
      ansible.builtin.command: ip -6 addr add fd00:dead:beef::10/64 dev dummy0
      register: dummy_addr
      changed_when: dummy_addr.rc == 0
      failed_when: dummy_addr.rc != 0 and 'File exists' not in dummy_addr.stderr

    - name: Ensure the TLS staging directory exists
      ansible.builtin.file:
        path: /etc/letsencrypt/live/mesh.example.net
        state: directory
        mode: "0755"

    - name: Generate a self-signed test certificate with DNS and IP SANs
      ansible.builtin.command: >
        openssl req -x509 -newkey rsa:2048 -nodes -days 1
        -keyout /etc/letsencrypt/live/mesh.example.net/privkey.pem
        -out /etc/letsencrypt/live/mesh.example.net/fullchain.pem
        -subj "/CN=piccolo-perf-test.mesh.example.net"
        -addext "subjectAltName=DNS:piccolo-perf-test.mesh.example.net,IP:fd00:dead:beef::10"
      args:
        creates: /etc/letsencrypt/live/mesh.example.net/fullchain.pem

    - name: Trust the test certificate as a CA so Go's http client accepts it
      ansible.builtin.copy:
        src: /etc/letsencrypt/live/mesh.example.net/fullchain.pem
        dest: /usr/local/share/ca-certificates/piccolo-perf-test.crt
        remote_src: true
        mode: "0644"

    - name: Refresh the system CA trust store
      ansible.builtin.command: update-ca-certificates
      changed_when: true

    - name: Map the test mesh hostname to the dummy interface address
      ansible.builtin.lineinfile:
        path: /etc/hosts
        line: "fd00:dead:beef::10 piccolo-perf-test.mesh.example.net"
        create: true

    - name: Write a fixture topology config for the stub config server
      ansible.builtin.copy:
        dest: /var/www/html/piccolo-config.json
        content: |
          {
            "topology": "mesh",
            "config_refresh": "5m",
            "hide_skipped": false,
            "hosts": [
              { "name": "piccolo-perf-test", "address": "fd00:dead:beef::10", "site": "test" }
            ],
            "hub_spoke": { "enabled": false, "hub": "" },
            "measurements": [
              { "type": "dns", "interval": "120s", "resolvers": ["2620:fe::fe"], "names": ["example.com"] }
            ],
            "influxdb": { "url": "", "token": "", "org": "", "bucket": "" },
            "local_store": { "enabled": false, "path": "/var/lib/piccolo-perf/results.jsonl", "max_lines": 10000 }
          }
        mode: "0644"

    - name: Configure nginx as a stub HTTPS config server for this test only
      ansible.builtin.copy:
        dest: /etc/nginx/conf.d/config-stub.conf
        content: |
          server {
            listen [fd00:dead:beef::10]:8443 ssl;
            ssl_certificate /etc/letsencrypt/live/mesh.example.net/fullchain.pem;
            ssl_certificate_key /etc/letsencrypt/live/mesh.example.net/privkey.pem;
            root /var/www/html;
          }
        mode: "0644"

    - name: Start the stub config server
      ansible.builtin.systemd:
        name: nginx
        state: restarted
        enabled: true
```

- [ ] **Step 3: Create `roles/piccolo_perf/tasks/install.yml`**

```yaml
---
- name: Check installed piccolo-perf version
  ansible.builtin.command: "{{ piccolo_perf_binary_path }} -version"
  register: piccolo_perf_installed_version
  changed_when: false
  failed_when: false

- name: Download and install piccolo-perf {{ piccolo_perf_version }}
  when: piccolo_perf_version not in (piccolo_perf_installed_version.stdout | default(''))
  block:
    - name: Download checksums.txt
      ansible.builtin.get_url:
        url: "{{ piccolo_perf_checksums_url }}"
        dest: "/tmp/piccolo-perf-checksums-{{ piccolo_perf_version }}.txt"
        mode: "0644"

    - name: Extract expected checksum for this platform's asset
      ansible.builtin.shell: |
        set -o pipefail
        grep '{{ piccolo_perf_asset_name }}' /tmp/piccolo-perf-checksums-{{ piccolo_perf_version }}.txt | awk '{print $1}'
      args:
        executable: /bin/sh
      register: piccolo_perf_expected_checksum
      changed_when: false

    - name: Download and verify the piccolo-perf release archive
      ansible.builtin.get_url:
        url: "{{ piccolo_perf_release_url }}"
        dest: "/tmp/{{ piccolo_perf_asset_name }}"
        checksum: "sha256:{{ piccolo_perf_expected_checksum.stdout }}"
        mode: "0644"

    - name: Extract the piccolo-perf binary
      ansible.builtin.unarchive:
        src: "/tmp/{{ piccolo_perf_asset_name }}"
        dest: /tmp
